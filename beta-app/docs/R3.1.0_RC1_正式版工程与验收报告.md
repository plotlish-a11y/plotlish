# Plotlish R3.1.0-rc.1 | 正式版工程基础与待验收项目

> **状态：Release Candidate / PRE-PRODUCTION，不能直接当作 V1.0.0 已上线版本。** 本次不提交 GitHub，不接触 Cloudflare 凭据，不部署正式网站。

## 基线和目标

- 继承 R3.0.4 的右侧上下图文布局、Logo、暖白色调、小说详情满屏背景、句下翻译、在线词典、TTS、阅读进度接口及独立课程导入。
- 课程正文、封面、人物图、剧情图继续由 `course-packages/` 单独导入；交付包没有课程素材。
- beta 测试站流水线原样保留；新增正式站工作流，不从 beta 分支发布 production。

## 此次实质改动

1. `core/src/reader.js`: 合并字号、行距和窗口尺寸变更触发的分页测量入口；设置变更时先应用几何参数、后分页，排队合并变化，并加下一帧校验。旧的“同步测量 + setTimeout 重新测量”机制不再并行竞争。
2. 新增 `tools/verify_production_site.py`: 正式发布必须至少有一部公开作品和一章公开课程；校验章节 ID、句子 ID、中文数量及内容引用，拒绝空白译文和逃逸路径。
3. 新增 `tools/create_release_manifest.py`: 在已验证发布产物中生成 `release.json`，含代码提交 ID、版本号、目录及程序文件 SHA-256，供线上比对。
4. 新增 `tools/check_production_cloudflare_target.py`: 校验项目必须是 `plotlish`，域名必须是 `plotlish.pages.dev`，生产分支必须是 `main`，否则拒绝发布；如果检测到 GitHub 集成且未明确授权，则同样拒绝。
5. 新增 `.github/workflows/plotlish-production.yml`: 只允许手动触发，确认词 `PUBLISH_PLOTLISH`，只能从 `main` 执行；先验证源码、课程及浏览器，再上传经过审批的产物到现有 Pages 正式项目；发布后核对线上 manifest。
6. 新增 `tests/test_release.py`、`tests/browser_smoke.py`：生产门禁单元测试和无需真实课程的 Chromium 交互检查。

## 如何准备正式上线

1. `main` 分支必须确认为正式发布分支；在 GitHub 新建名为 `plotlish-production` 的 Environment，配置 Required reviewers（受仓库权限限制时参考 GitHub 文档），并限制允许部署的分支为 main。
2. 在该 Environment 配置两个独立于 Beta 的 secrets：`CLOUDFLARE_API_TOKEN_PROD`、`CLOUDFLARE_ACCOUNT_ID_PROD`；不要复制开发环境凭据。
3. 管理员检查 Cloudflare 中现有 `plotlish` 项目：确定 production_branch/main 关系与 Git 自动部署状态。若启用 Git 集成，先核实并关闭冲突的自动生产构建，经确认后才把 `ALLOW_GIT_INTEGRATED_PROD=true` 设置为 Environment Variable。
4. 课程导入 `course-packages/`，只允许确定公开的章节标记为 published。不可为了通过门禁而将草稿改为 published。
5. 先在 Beta 测试环境验证构建；完成上述 P0 后，再在 GitHub Actions 的 Production workflow 上手动填写版本号和确认词，等待环境批准。没有通过门禁的工作流不会推送正式站。
6. 记录上线前部署 ID，并利用 Cloudflare Pages Deployments 进行回滚。回滚前保留旧构建和本地学习记录，不重置浏览器存储。

## 本地执行

```sh
cd beta-app
python -m unittest discover -s tests -p 'test_*.py' -v
python tests/browser_smoke.py  # 需要事先安装 playwright 和 Chromium
python tools/build.py --packages-dir ../course-packages
python tools/verify_beta_site.py            # 空课程允许
python tools/verify_production_site.py      # 空课程必须拒绝
```

> 注意：正式版源码包与“带课程的正式站产物”应分别保管。源码包不带任何内容；正式站产物需使用获准公开的课程构建。
