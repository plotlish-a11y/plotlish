# R2.4 课程存储与发布标准

## 结构约定

一部小说一个文件夹、一个章节一个可编辑的目录；封面归属于整本小说，图片归属于各自章节；所有项目均通过 `book_id` 和 `chapter_id` 做稳定识别。

```text
packages/
  README.md
  my-first-book/
    book.json
    cover.webp                    # 可选；真实的 WebP 图片
    chapters/
      ch001/
        course.json
        glossary.json             # 可选：{ "word": "中文释义" }
        images/                   # 可选
          opening.webp
      ch002/
        course.json
  another-book/
    book.json
    chapters/
      ch001/
        course.json
```

**不要在 `packages/` 根目录放 ZIP 或直接散放章节。** 文件夹、ID、发布状态必须严格匹配。

## 作品 book.json

```json
{
  "schema_version": "plotlish-book-v1",
  "book_id": "my-first-book",
  "title": "My First Book",
  "title_zh": "我的第一本书",
  "genre": "Fantasy",
  "level": "B1",
  "synopsis": "Brief English story description.",
  "status": "draft"
}
```

必填：`schema_version`、`book_id`、`title`、`level`、`genre`、`status`。选填：`title_zh`、`synopsis`、`cover.webp`。封面只放书籍根目录，不必各章重复。

## 章节 course.json

```json
{
  "chapter_id": "my-first-book-ch001",
  "chapter": "Chapter 1: The Letter",
  "subtitle": "The first clue",
  "status": "draft",
  "sentences": ["She found a letter.", "It was addressed to her."],
  "ids": ["my-first-book-ch001-s001", "my-first-book-ch001-s002"],
  "translations": ["她发现了一封信。", "信是写给她的。"],
  "annotations": [{
    "id": "my-first-book-ch001-note01",
    "sentenceIndex": 0,
    "phrase": "found a letter",
    "meaning": "发现了一封信",
    "explain": "find 的过去式是 found。"
  }],
  "paragraphBreaks": [0],
  "grammar": {"term": "Simple past", "explain": "Past tense for completed actions.", "example": "She found a letter."},
  "question": "What did she find?",
  "questionHelp": "Answer in one English sentence.",
  "scenes": [{
    "scene_id": "letter-on-table",
    "start_index": 0,
    "title": "The Letter",
    "alt": "A folded letter on a wooden table"
  }]
}
```

此例需要同目录下 `images/letter-on-table.webp`。没有插图可将 `scenes` 设为空数组并省略 `images/`。没有知识点时 `annotations` 可为 `[]`。`grammar`、`question`、`questionHelp` 是章节读后复盘用的可选字段；省略时会自动使用安全的默认文本。如果需要悬浮词义，另外放置 `glossary.json`，例如 `{"letter": "信件"}`。

`chapter_id` 必须以作品 `book_id` 开头，以章节编号结尾，且 `ch001` 目录对应编号 001。`sentences`、`ids`、`translations` 必须等长，且不能是空数组。句子 ID 与知识点 ID 在全部作品中必须唯一。`annotation.sentenceIndex` 从 0 开始。

`book`、`book_id`、`genre`、`level`、`synopsis` 在构建时由 `book.json` 统一补充；不必在每个章节重复。保留旧 ZIP 中的这些字段时必须与 `book.json` 一致。

## 发布状态

| 书籍状态 | 章节状态 | 网站显示 |
| --- | --- | --- |
| draft | draft | 不显示 |
| draft | published | 不显示 |
| published | draft | 不显示 |
| published | published | 显示 |

所有章节（包括 draft）都会被校验：出现不规范的数据时构建失败，以免发布错误的数据。仅在 public `dist/` 输出已发布章节正文、封面及相关插图。没有已发布章节时书架仍然显示“暂无课程”。

## 旧版单章 ZIP 导入

ZIP 必须直接包含 `course.json`（可含 `glossary.json`、`images/*.webp`、`cover.webp`），不能多套一层目录。导入程序校验路径、文件数量及大小，拒绝绝对路径、路径穿越与符号链接；默认导入为 draft。用法：

```powershell
python tools/import_chapter.py --book my-first-book --zip "C:\Courses\my-first-ch01.zip"
```

可选 `--replace` 覆盖已存在章节，`--publish` 导入即发布，`--replace-cover` 替换已有封面。**覆盖时要小心：句子 ID 的变化可能影响现有学生学习记录。**

## 自动构建与前端兼容

1. 递归扫描 `packages/<book-id>/chapters/chNNN/`，先检验所有源文件。
2. 仅收集已发布章节，按作品 ID + 章节序号生成书架目录 `courses/catalog.json`。
3. 每个章节输出 `courses/<chapter_id>.json`，书籍封面位于 `assets/covers/<book_id>.webp`。
4. 每章插图输出 `assets/scenes/<book_id>/<chapter_id>/<scene_id>.webp`，不同章节同名场景不会冲突。
5. 保持阅读器接口 `plotlish-r231-web-v2` 不变。阅读器仍然仅加载当前章节的完整正文，其余章节读目录元数据。
6. 构建采用临时输出、验证后替换；输入有错不会先删除上次已经成功构建的 `dist/`。
7. 私有课程源和草稿不会复制到网站静态目录；GitHub 私有仓库仍然保留相应源文件及 Git 历史。

## 运行与验收

在 `beta-app` 目录运行：

```powershell
python -m unittest discover -s tests -p test_build.py -v
python tools/build.py
python tools/verify_beta_site.py
```

空书架、单本多章、多本课程、草稿过滤、插图文件、章节编号、重复 ID、无效 JSON、ZIP 路径穿越、安全覆盖等都包含测试。**GitHub Actions 成功部署后仍建议在浏览器核对页面和多章节切换。**
